# Windowed 多窗口与网页文件上传修复设计

## 背景

当前 `Windowed` 采用单窗口、全局 URL 状态的实现方式：

- `App.swift` 使用全局 `@AppStorage("savedURL")` / `@AppStorage("savedName")`
- `ContentView` 围绕唯一的当前 URL 工作
- `URLInputSheet` 中点击历史预设会直接覆盖当前窗口
- `WebView` 已接入 JavaScript 弹窗代理，但未实现网页文件选择代理

这导致两个直接问题：

1. 一个 App 内无法同时打开多个独立网页窗口
2. 网页中的文件上传控件点击后无法弹出访达选择文件

## 本次目标

本次一期只实现最小可用版本：

1. 支持单 App 多窗口
2. 每个窗口拥有独立的 URL、名称、服务状态和刷新行为
3. 修复网页中的文件、图片、照片文件选择
4. 保持现有预设能力，包括历史、置顶、图标、启动命令、停止命令

## 明确不在一期内的内容

以下内容暂不纳入本次实现：

- 退出 App 后自动恢复上次打开的多个窗口
- 自动恢复多个窗口对应的本地服务
- 同一服务被多个窗口共用时的引用计数停服
- `window.open()` 自动映射为新的原生窗口
- 摄像头、麦克风、相册权限流

补充说明：

- 一期允许恢复“上次最后使用的单个页面”
- 一期不恢复“上次全部窗口会话”

## 设计原则

1. 在现有 SwiftUI + `WindowGroup` 架构上演进，不切到重型 AppKit 窗口控制器方案
2. 预设是模板，窗口是实例，两者分离
3. 一期优先解决主要用户路径，不引入额外状态复杂度
4. 代码改动集中在少量核心文件，便于验证与回归

## 方案概览

### 1. 引入窗口实例模型

新增 `WindowConfig`，作为单个窗口运行时的独立配置：

- `id`
- `url`
- `name`
- `iconPath`
- `startCommand`
- `stopCommand`
- `stopOnClose`

其中：

- `URLEntry` 继续作为“预设模板”
- `WindowConfig` 作为“窗口实例”
- 从历史预设或手动输入打开页面时，都会生成一份独立 `WindowConfig`
- Dock 图标固定使用 `Windowed` 默认图标，不跟随窗口或预设切换

### 2. App 入口切换为多窗口

`App.swift` 调整为以 `WindowConfig` 为值的 `WindowGroup`：

- 允许同一个 App 打开多个浏览窗口
- 保持一个 Dock 图标，不拆成多个 App
- 增加 `⌘N` 新建窗口入口
- 保留 `⌘U` 打开当前窗口设置

新建窗口分两类：

- 空白窗口：先显示设置面板，等待输入 URL
- 预设窗口：直接带着 `WindowConfig` 打开

### 3. ContentView 改为窗口级状态

`ContentView` 不再依赖全局 `savedURL` / `savedName`，改为接收当前窗口的独立配置。

每个窗口独立持有：

- 当前 URL
- 窗口名称
- 设置面板显示状态
- `ServiceStarter`
- 刷新 token
- 关闭窗口时的 stop 行为

这样可以保证多个窗口之间互不覆盖、互不串状态。

### 4. 预设面板调整为“模板 + 打开动作”

`URLInputSheet` 保留现有能力，但语义调整如下：

- 手动填写后点击打开：应用到当前窗口
- 历史预设点击：默认在新窗口打开
- 编辑预设：仍在当前设置面板中完成
- 保存逻辑继续写入 `urlPresets`

这能让历史预设的行为更符合“多开”的直觉。

### 5. 修复网页文件上传

`WebView.Coordinator` 补充 `WKUIDelegate` 的文件选择代理：

- 实现 `runOpenPanelWithParameters`
- 用 `NSOpenPanel` 弹出原生访达文件选择面板
- 支持单选 / 多选
- 正确将所选文件 URL 回传给网页
- 用户取消时返回 `nil`

修复后，网页中的以下场景应恢复正常：

- 上传文件
- 上传图片
- 上传多张图片
- 上传本地照片文件

## 关键取舍

### 1. 一期不做窗口恢复

“窗口恢复”指的是退出 App 后，下次启动自动把上次开的多个窗口重新打开。

暂不实现的原因：

- 不是当前主痛点
- 需要定义恢复哪些字段、何时清理无效窗口、何时重启服务
- 会把多窗口改造和会话持久化耦合在一起

补充：

- 本期只保存并恢复最后使用的单个页面配置，作为启动默认入口

### 2. 一期不做服务恢复

“服务恢复”指恢复窗口时，是否顺带自动执行 `startCommand` 再拉起本地服务。

暂不实现的原因：

- 可能导致用户一启动 App 就批量拉起本地服务
- 需要更清晰的用户预期和失败处理策略

### 3. 一期沿用现有 stop-on-close 行为

每个窗口仍按自身配置决定是否在关闭时执行 `stopCommand`。

已知限制：

- 如果两个窗口共用同一个本地服务，先关闭其中一个窗口，可能把另一个窗口正在使用的服务停掉

本问题保留到后续“服务引用计数”版本再解决。

## 测试要点

### 多窗口

- 可连续创建多个窗口
- 不同窗口可打开不同 URL
- 一个窗口切换预设时不会覆盖其他窗口
- 每个窗口标题正确展示

### 本地服务

- 绑定 `startCommand` 的本地窗口可以正常拉起服务
- 只刷新当前窗口，不影响其他窗口
- 关闭启用 `stopOnClose` 的窗口时会执行 stop 命令

### 文件上传

- OpenClaw 等本地服务页面点击上传时可弹出访达
- 支持上传单文件
- 支持上传多文件
- 用户取消选择不会导致页面异常

### 启动与窗口尺寸

- 有上次使用页面时，启动后直接恢复该页面
- 无上次使用页面时，启动后进入空白配置窗口
- 空白配置窗口会按当前屏幕可视区域约 `70%` 宽、`80%` 高显示

## 协作与分支策略

建议后续按以下流程协作：

1. 新功能或修复默认先新建分支
2. 分支上完成修改和测试
3. 验证通过后再合并回 `master`

建议命名：

- 功能：`feat/multiwindow-upload`
- 修复：`fix/<topic>`
- 文档：`docs/<topic>`

当前已有分支建议：

- `fix/safety-and-dialogs`：其内容已体现在历史提交中，可在确认不再需要后删除本地分支
- `backup-before-rebase`：当前与 `master` 指向同一提交，可保留一段时间作为保险，确认无用途后删除
